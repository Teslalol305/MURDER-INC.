# The sound gate of a package (version 3b on): a queue for lag-test.sh on the unpacked zip, as a host starts it.
#
#   unzip the zip as the user e3dsfresh into a folder, then
#   LAG_BUILD=<that folder> LAG_RUNAS=fresh LAG_CLEAN=1 bash lag-test.sh queue sound-gate.txt      (10 runs, about 27 minutes)
#   bash lag-test.sh list
#
# Nothing else may run on the box meanwhile (no compile, no package, no analysis: numpy takes every core, and a box
# whose CPUs are all busy puts holes into the sound; the note under the list). The box is shared: every summary says
# how busy its CPUs were ("the box's CPUs: 62 % busy in the viewer's first 40 s (busiest second 81 %), 30 % after
# them") and whether a compiler, a cook or an editor of another job ran beside the run ("A COMPILER, A COOK OR AN
# EDITOR ran beside it in 51 of 87 samples": version 3b's release met one and had 41 holes in that line's first half
# minute, none in its repeat), so a line that met a busy box can be told from a line that failed.
# It passes when every line says CLEAN and:
#   every line   "sound: ... 0 without an asset, 0 without an audio device"
#   every line   no drop-out in the play: the summary says when the first and the last drop-out were and under which
#                of the script's markers they fell ("by the script's markers: card 2, home 5, briefing 6"): none from
#                the marker "run" on, and for snd-dev (its script has no markers) none after the first 40 s of the
#                recording
#   snd-dev, snd-keys, snd-env, snd-free, snd-l20-late, snd-l20-c12, snd-cpu6-l35
#                on a quiet box no digital silence, nothing lost and no drop-out at all (the music and the street never
#                stop). With drop-outs in the first half minute and the box's CPUs about 90 % busy or more in the
#                viewer's first 40 s, the line met a busy box (the note below): run it again before blaming the package
#   snd-l20, snd-l35
#                these two bring the box nearest its limit by themselves (the load process beside a cold start on all
#                16 CPUs): drop-outs under card, home and briefing are the box. Measured for version 3b: 13 and 4 while
#                the desktop's browser played a stream beside them, 0 and 0 half an hour later when it did not
#   snd-dev      the Development game plays a whole Story run by its own demo director (sound-demo.txt) and logs every
#                sound it starts: python3 sound_table.py /project/ue/cloud/lag/snd-dev --audio <Content/Audio> prints
#                one line per sound: found in the recording or not, how far above chance, its level, its delay.
#                Measured for version 3b: PROGRESS.md "Version 3b: sound"
#   snd-keys     the Shipping game played with mouse and keyboard, one kind of sound at a time (sound-keys.txt):
#                bash sound-keys-check.sh /project/ue/cloud/lag/snd-keys says what was found in every part, the
#                delay from each fire input to the gun's sound, each part's level, and what forty presses on the
#                Volume row did (80 % to 40 %: the music on the pause card must fall by about 6 dB, and come back)
#   snd-env      the launcher started with SDL_AUDIODRIVER=alsa and SDL_AUDIO_DEVICE_SAMPLE_FRAMES=960 in its
#                environment, on a machine with no sound card: the game must sound all the same (the launcher names
#                SDL's dummy device itself; without that the game opens no audio device and is silent)
#   snd-nosvc    the launcher started with SDL_AUDIODRIVER=pulseaudio and the address of a sound service that does
#                not exist (PULSE_SERVER, XDG_RUNTIME_DIR): a host whose environment expects a sound service on a
#                machine that runs none. The same must hold: the launcher's "sound:" line names what the host set,
#                and the game sounds
#   snd-free, snd-l20, snd-l35, snd-cpu6-l35   the Shipping game with the GPU free and loaded as in lag-gate.txt (the
#                game then runs at 60, 45 and 30 frames a second), five single rounds, a burst and a fast turn
#                (sound-short.txt): fps and worst frame as in the release gate, and
#                audio_find.py <run>/sound.wav --part single-shots Gen/chopper_close_01.wav Gen/chopper_close_02.wav
#                  Gen/chopper_close_03.wav --action click --audio <Content/Audio>
#                gives the delay from each fire input to the arrival of the gun's sound
#   snd-l20-late the same load, the viewer joins 55 s after the game's first probe line: the cold start is over
#   snd-l20-c12  the same load from the first second, the game on 12 of the box's 16 CPUs (the load, the viewer and
#                the desktop keep the other four)
#
# The first half minute of a cold start. A game that has never run on a machine compiles its pipeline states for
# about 30 s on three quarters of the CPUs (Unreal's precompile pool: twelve threads on this box, each 70 to 90 %
# busy). On this box the load process, the viewer and the desktop's browser take two to three CPUs more, all 16 are
# then busy, the game's sound threads wake late, and Pixel Streaming's sender leaves holes of 30 to 50 ms in the
# sound's time line (the sound itself goes on where it stopped). Measured for version 3b (PROGRESS.md, section 8):
# with the load and a busy desktop 4 to 22 holes in that half minute and none after it, in the menus or in the play;
# none at all when the game keeps off four CPUs, when the viewer comes after the half minute, or on a quiet box; 57 on
# a free GPU with two busy loops beside the game, and once 115 in the Development game's line on a free GPU while
# something else was busy on the box. The Development game's cold start alone takes the box to 86 to 95 % for 33 s.
# It is the box's CPUs, not the GPU's load and not the frame rate.
snd-dev game=dev demo=sound-demo.txt view=sound-watch.txt audio=1 join=3 probe=0.25 secs=330 -- -ini:Engine:[Core.Log]:LogMIAudioHost=Verbose
snd-keys game=ship view=sound-keys.txt audio=1 join=3 probe=0.25 secs=160
snd-env game=ship view=sound-short.txt audio=1 join=3 probe=0.25 secs=95 env=SDL_AUDIODRIVER=alsa,SDL_AUDIO_DEVICE_SAMPLE_FRAMES=960
snd-nosvc game=ship view=sound-short.txt audio=1 join=3 probe=0.25 secs=95 env=SDL_AUDIODRIVER=pulseaudio,PULSE_SERVER=unix:/nonexistent/pulse,XDG_RUNTIME_DIR=/nonexistent
snd-free game=ship view=sound-short.txt audio=1 join=3 probe=0.25 secs=95 load=0
snd-l20 game=ship view=sound-short.txt audio=1 join=3 probe=0.25 secs=95 load=1:0.05:0:1024
snd-l35 game=ship view=sound-short.txt audio=1 join=3 probe=0.25 secs=95 load=1:0.3:0
snd-cpu6-l35 game=ship view=sound-short.txt audio=1 join=3 probe=0.25 secs=95 load=1:0.3:0 cpus=0-5
snd-l20-late game=ship view=sound-short.txt audio=1 join=55 probe=0.25 secs=150 load=1:0.05:0:1024
snd-l20-c12 game=ship view=sound-short.txt audio=1 join=3 probe=0.25 secs=95 load=1:0.05:0:1024 cpus=0-11
